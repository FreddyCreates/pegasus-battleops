║                           I. PREAMBLE                                     ║
╚═══════════════════════════════════════════════════════════════════════════╝

WHEREAS the Spatium Computationis ecosystem is a living computational
organism operating under the Nova Sovereign Protocol, designed to grow,
adapt, and evolve through disciplined inquiry;

WHEREAS the ecosystem governs intelligent automation for the Casa de Medina
operational environment including furniture installation estimating, field
operations, project documentation, and design interpretation;

WHEREAS research activities carry inherent risks to data integrity,
operational stability, computational sovereignty, and system safety;

WHEREAS the advancement of the ecosystem requires a formalized framework
that balances innovation with governance, creativity with accountability,
and exploration with protection;

WHEREAS the φ-derived mathematical primitives form the computational
foundation and all research must respect this mathematical sovereignty;

NOW THEREFORE, this Research Charter is enacted as the master governance
document for all research activities within Spatium Computationis.

║                    IV. RESEARCH LIFECYCLE                                  ║
╚═══════════════════════════════════════════════════════════════════════════╝

All research follows a governed lifecycle:

  ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
  │ PROPOSED │ ──► │ APPROVED │ ──► │  ACTIVE  │ ──► │ REVIEW   │
  └──────────┘     └──────────┘     └──────────┘     └──────────┘
       │                                  │                │
       │                                  │                │
       ▼                                  ▼                ▼
  ┌──────────┐                    ┌────────────┐    ┌───────────┐
  │ REJECTED │                    │ SUSPENDED  │    │ COMPLETED │
  └──────────┘                    └────────────┘    └───────────┘
                                        │
                                        ▼
                                  ┌────────────┐
                                  │ TERMINATED │
                                  └────────────┘

Phase Transitions and Authority:

  PROPOSED → APPROVED      Committee authority required
  PROPOSED → REJECTED      Committee authority (insufficient scope/ethics)
  APPROVED → ACTIVE        Principal investigator authority
  ACTIVE → REVIEW          Automatic at milestones, or on-demand
  ACTIVE → SUSPENDED       Safety override (immediate, no approval needed)
  REVIEW → COMPLETED       Committee authority + deliverables verified
  REVIEW → ACTIVE          Continue with revisions (Principal authority)
  SUSPENDED → ACTIVE       Safety review cleared + Committee approval
  SUSPENDED → TERMINATED   Constitutional authority (irrecoverable)

╔═══════════════════════════════════════════════════════════════════════════╗
║               VI. PROTOCOL SPECIFICATION                                  ║
╚═══════════════════════════════════════════════════════════════════════════╝

The Research Charter Protocol (Protocol VII) implements:

  Module: spatium-computationis/protocols/research_charter.py
  Glyph:  ⊛ (Research — formalized inquiry under protocol)

  OPERATIONS:

  1. create_charter(...)
     Creates a new charter in PROPOSED phase with default governance
     bindings automatically applied.

  2. approve_charter(charter_id, approver, notes)
     Transitions PROPOSED → APPROVED. Requires Committee authority.

  3. activate_charter(charter_id)
     Transitions APPROVED → ACTIVE. Sets start date.

  4. complete_charter(charter_id, summary)
     Transitions ACTIVE → COMPLETED. Records end date.

  5. suspend_charter(charter_id, reason)
     Transitions any phase → SUSPENDED. Safety override authority.

  6. get_charter(charter_id)
     Retrieve charter by ID.

  7. list_charters(domain, phase, principal_investigator)
     Query charters with optional filters.

  8. get_active_charters()
     List all currently active research.

  9. add_milestone(charter_id, title, description, target_date)
     Register a milestone within a charter.

  10. add_deliverable(charter_id, title, description, type, milestone_id)
      Register a deliverable.

  11. validate_charter_compliance(charter)
      Validate against all governance bindings.

  DATA MODELS:

  • ResearchCharter      — Complete charter document
  • ResearchObjective    — Individual research objective
  • EthicalBoundary      — Ethical constraint definition
  • ResearchMilestone    — Timeline milestone
  • ResearchDeliverable  — Output artifact
  • GovernanceLawBinding — Link to governance law

  DELIVERABLE TYPES:

  • PROTOCOL             — New or revised protocol
  • ALGORITHM            — Mathematical or computational method
  • DATASET              — Curated data for system use
  • MODEL                — Trained model or decision framework
  • REPORT               — Written analysis or findings
  • TOOL                 — Software tool or utility
  • GOVERNANCE_AMENDMENT — Proposed governance change

╔═══════════════════════════════════════════════════════════════════════════╗
║               VIII. COMPLIANCE VALIDATION                                 ║
╚═══════════════════════════════════════════════════════════════════════════╝

The system provides runtime compliance validation:

  1. STRUCTURAL VALIDATION (at charter creation):
     - Objectives have measurable criteria
     - Ethical classification is present
     - Principal investigator is designated
     - Abstract is substantive (≥10 characters)
     - Methodology references no forbidden external LLMs

  2. GOVERNANCE REVIEW (at approval):
     - All mandatory bindings satisfied
     - Ethical boundaries defined for classification level
     - Authority chain appropriate for scope
     - No Constitutional violations detected

  3. RUNTIME ENFORCEMENT (during active phase):
     - Safety rules retain override authority
     - Pipeline compliance enforced by Procedural rules
     - Audit trail maintained per PROC-002
     - Feedback integration per RCL-09

  4. COMPLETION VALIDATION (at charter close):
     - Deliverables produced and registered
     - Outcomes fed back to learning loop
     - Data archived per RCL-11
     - Final compliance report generated
